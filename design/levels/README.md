# 章の作り方

章ごとの場面・手がかりの配置を作るときの、共通の決まりを書きます。
各章の具体的な展開・手がかりの配置は、ネタバレになるためリポジトリでは管理しません。

## 場面の組み立て

- 1 つの章は、導入 → 調査 → 判断 → 結末 の流れを基本にする。
- 判断の場面からは、調査の場面に戻れるようにする（手がかりを集め直せるようにするため）。
- 結末は「通常解決」と「真解決」の 2 つを用意する。

## 手がかりの置き方

- 真解決に必要な手がかりは、章ごとに 3 つ程度にする。
- 少なくとも 1 つは、選択肢ではなく「カメラ・映像モードの切り替え」を自分で試さないと得られないものにする。
- 切り替えで得る手がかりは、物語でそのカメラを見る理由ができてから得られるようにする（`onView` の `requires`）。
- 切り替えが必要なことは、文章でそれとなくヒントを出す。

## フラグの名前

| 種類 | 名前の付け方 | 例 |
|---|---|---|
| 進行 | 内容がわかる英語 | `cam_unlocked` |
| 手がかり | `clue_` で始める | `clue_shadow` |
| 解決 | `resolved_normal` / `resolved_true` | — |

- 章が増えたら、章ごとに区別できるようにする（例: `ch1_clue_xxx`）。**未実装**（今のデモは章の区別なし）。

## 難易度の考え方

- 選択肢だけを選んでいくと、通常解決になる。
- 真解決には、プレイヤーが自分で映像を調べる必要がある。
