# 章の作り方

章ごとの場面・手がかりの配置を作るときの、共通の決まりを書きます。
各章の具体的な展開・手がかりの配置は、ネタバレになるためリポジトリでは管理しません。

## 場面の組み立て

- 1 つの章は、導入 → 調査 → 判断 → 結末 の流れを基本にする。
- 判断の場面（`@choice`）では、カメラ・過去の時刻を自由に動かせる（探索）。調査の場面に戻れるようにして、手がかりを集め直せるようにする。
- 結末は「通常解決」と「真解決」の 2 つを用意する（最終章は、選択で分かれるエンディング）。
- 失敗した選択は、短いバッドエンド（`@ending bad`）にして、選択の直前からやり直せるようにする。パズルの失敗は `@miss` のカードにする。
- 章の終わりには `@result`（章の結末の記録）、`@trueready`（真解決ができる）、`@next`（次の章）などを使う。

## 手がかりの置き方

- 真解決に必要な手がかりは、章ごとに 3 つ程度にする。
- 少なくとも 1 つは、選択肢ではなく「カメラ・映像モードの切り替え」を自分で試さないと得られないもの（`@look`・`@event`）にする。
- 切り替えで得る手がかりは、物語でそのカメラを見る理由ができてから見つかるようにする（`@event` の条件・`@feed` の置き方）。
- 切り替えが必要なことは、文章でそれとなくヒントを出す。行き詰まりやすい場面には、1 回目は考え方、2 回目から具体的な場所、と段階を上げるヒントを置く。

## フラグの名前

| 種類 | 名前の付け方 | 例 |
|---|---|---|
| 進行 | 内容がわかる英語。章のフラグは、台本ごとに独立（`state.flags`）で、章をまたがない | `cam_unlocked` |
| 章をまたぐ | `@gset` / `@gunset`。条件は `g:フラグ` で書く。「送った一枚」は `relay_ch<N>` | `relay_ch2` |
| 結末 | `@result`・`@trueready` で記録する（フラグではなく、章の記録 `progress.chapters`） | − |

## 難易度の考え方

- 選択肢だけを選んでいくと、通常解決になる。
- 真解決には、プレイヤーが自分で映像を調べる必要がある。
- 時間切れ（`@idle`）を使う場面でも、同じ結末へ進めるボタンの選択肢を残す（時間切れを「なし」にできるようにするため）。
