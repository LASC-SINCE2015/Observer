# 0005 シナリオを台本形式（テキスト）で書き、仕組みも役割ごとのファイルに分ける

- 状態: 採用
- 日付: 2026-11-08

## 状況

シナリオはこれからも大きく書き換わっていく。[0004](0004_split_scenario_data_by_chapter.md) では、章ごとのデータを JS ファイルに分けると決めたが、JS のオブジェクト（`{ name: '…', text: '…' }` の並び）で書くと、文章を少し直すだけでも括弧や引用符の書き間違いが起きやすく、場面の流れも読み取りにくい。

## 決定

- シナリオは、章ごとの台本ファイル `game/scenario/chapter<N>.js` に、**テキストの台本**として書く。1 行が 1 回のクリックで出る文。セリフは `名前「…」`、命令は `@命令`、場面は `*ラベル`。書き方は [design/data/scenario_format.md](../data/scenario_format.md)。
- 台本ファイルは `Observer.script('名前', \`…\`)` の形の JS にして、`<script src>` で読み込む（ファイルを直接開いても動くように。テキストファイルを `fetch` で読む形は、`file://` では動かない）。
- カメラの一覧と章の一覧は `game/data/` に分ける（0004 のとおり）。
- 仕組みも、役割ごとに `game/js/`（台本の読み込み・描画・音・進行）と `game/css/` に分ける。0004 の「仕組みは index.html に残す」は、この ADR で置き換える。
- 仕組みにはシナリオに依存することを書かない。シナリオに新しい表現が必要になったら、命令・背景・人物の種類を足す形で、仕組みを広げる。
- 台本は、ブラウザなしで最後まで通して遊ぶ自動テスト（`tools/playtest.js`、Node.js）で確かめられるようにする。

## 理由

- 台本の形なら、文章を書く人がプログラムの書き方を気にせずに、場面の流れを上から読んで直せる。
- 読み込みのときに、ないラベル・ない命令を見つけて画面に出すので、書き間違いにすぐ気づける。
- 外部ライブラリもビルドもいらない方針（0001）を保てる。

## 影響

- 0004 の「仕組みは `game/index.html` に残す」「データは `game/data/chapter<N>.js`」は置き換え済み（台本は `game/scenario/`）。
- 台本の中では、バッククォートと `${` が使えない。
- 既読の記録は「台本の名前:行番号」で持つので、台本を書き換えると既読がずれることがある（遊び直しに困るほどではない）。
